# Локальные тестовые данные

```text
raw/         исходные локальные MP3
clips/       нарезанные MP3 и manifest.json
references/  ручные эталонные расшифровки в заданном формате JSON
```

Содержимое этих каталогов не включается в Git. Оригинальный MP3 можно также читать по абсолютному пути вне репозитория, без копирования.

Для проверки подкаста выберите несколько фрагментов по 30–90 секунд: монолог/чистый диалог, частые смены говорящего, перебивания. Избегайте музыкального вступления для базового теста. Это рекомендуемые длительности тестовых образцов, не ограничение конвейера.

Скопируйте `config/podcast_clips.example.json` в `config/podcast_clips.local.json`, укажите файл и реальные интервалы. Пример интервалов сам по себе не характеризует аудио.

```powershell
python -m dictophone prepare-clips config/podcast_clips.local.json
```

Для одного фрагмента:

```powershell
python -m dictophone cut "C:/audio/podcast.mp3" --start-ms 60000 --end-ms 120000 --output data/clips/podcast_01.mp3
```

Нарезка декодирует исходник последовательно до нужного места и перекодирует выбранные отсчёты в mono MP3 16 кГц. Время клипа начинается с нуля; исходный файл не меняется. Перекодирование может немного влиять на качество. Для сравнения моделей используйте одни и те же готовые фрагменты.

`manifest.json` хранит исходное смещение `source_offset_ms`. В экспортируемой расшифровке метки относятся к импортированному фрагменту; для перевода ко времени выпуска прибавьте это смещение. Нумерация говорящих действует внутри одного запуска, а не между независимыми клипами.

Текст эталона размечается вручную с прослушиванием. Нельзя использовать результат той же модели как «эталон» и считать по нему подтверждённый WER. Для монолога ожидается один участник, но это проверяется по аудио, а не задаётся алгоритму принудительно.
