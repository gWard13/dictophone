# Диктофон — Python-конвейер разработчика № 1

Реализован локальный конвейер `MP3 → слова со временем → диаризация → реплики → LLM → JSON` по предоставленному ТЗ. Это Python-библиотека и CLI. Все команды ниже выполняются из корня репозитория. Основная конфигурация теперь находится в config/pipeline.example.json; корневой config.example.json сохранён для совместимости.

## Быстрый старт (Windows PowerShell)

Используйте **Python 3.11 x64**. Python 3.14 из текущего окружения не является целевой версией для native-зависимостей проекта.

```powershell
py -3.11 -m venv .venv
.venv/Scripts/python.exe -m pip install --upgrade pip
.venv/Scripts/python.exe -m pip install -e .
.venv/Scripts/python.exe -m pip install "llama-cpp-python>=0.3,<0.4" --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
```

Если нет совместимого готового wheel для llama-cpp-python, потребуются CMake и Visual Studio Build Tools с C++. Не заменяйте локальную LLM облачным API.

Подготовка моделей — отдельный сетевой этап, без чтения пользовательского аудио:

```powershell
.venv/Scripts/python.exe scripts/prepare_models.py
Copy-Item config.example.json config.json
.venv/Scripts/python.exe -m dictophone doctor
```

Скрипт скачивает ASR small, модели диаризации и Qwen 0.5B Q4. Потребуется несколько гигабайт свободного места с учётом окружения, кэшей и временных данных. Для воспроизводимости задайте `--asr-revision` и `--llm-revision` конкретными commit hash; текущие значения по умолчанию — `main`, версии библиотек задаются диапазонами, поэтому подготовка не является полностью зафиксированной сборкой. После успешной установки сохраните `pip freeze` и `models/manifest.json`.

Файл `requirements-tested.txt` фиксирует проверенные версии для **Windows x64 / Python 3.11** и прямой URL wheel LLM. Его можно установить командой `python -m pip install -r requirements-tested.txt` из корня проекта. Для другой ОС потребуется подходящий wheel либо сборка llama-cpp-python. Проверка файлов весов без их загрузки в память: `python -m dictophone doctor --config config.json`.

Обработка:

```powershell
.venv/Scripts/python.exe -m dictophone run "C:/audio/dialog.mp3" --config config.json --output "result.json" --report "metrics.json"
```

После подготовки моделей можно отключить интернет. Модели загружаются только из локальных путей; запуск CLI устанавливает offline-переменные Hugging Face. Выбор языка — `--language ru` (по умолчанию) либо `en`. Имя результата по умолчанию получается заменой `.mp3` на `.json`, включая `.MP3`.

## Повтор только LLM

Обычный запуск не сохраняет приватную сессию. Для отладки и повтора постобработки явно укажите её:

```powershell
.venv/Scripts/python.exe -m dictophone run "C:/audio/dialog.mp3" --config config.json --session "private.session.json" --output result.json
.venv/Scripts/python.exe -m dictophone retry-llm private.session.json --config config.json --output corrected.json
```

Сессия содержит слова, временные интервалы диаризации и исходные реплики ASR. Она не нужна для обычного экспорта и содержит конфиденциальный текст: удалите её после работы. Без --session приватная промежуточная расшифровка на диск не записывается.

## Алгоритм

1. **Декодирование:** PyAV потоково переводит MP3 в mono float32 PCM 16 кГц во временном каталоге. Исходник не изменяется. Данные открываются через memory map. Паузы не вырезаются из общей временной шкалы.
2. **ASR:** faster-whisper / CTranslate2, CPU INT8, явно выбранный язык и временные метки слов. Используется локальная директория модели. Ошибка ASR останавливает обработку. Встроенный VAD включается через `asr.vad_filter`; по умолчанию выключен, поскольку на проверенном коротком русском примере он отбрасывал полезную речь. Отсутствие речи также оценивается средствами ASR и диаризации.
3. **Диаризация:** sherpa-onnx, pyannote segmentation 3.0 + 3D-Speaker embedding + автоматическая кластеризация (`num_clusters=-1`, стартовый `threshold=0.6`). Фиксированное число участников не задаётся. При ошибке все слова получают `unknown`, в отчёт добавляется предупреждение. Нехватка памяти/диска считается критической ошибкой. Порог требует проверки на ваших диалогах; меньшие значения могут избыточно разделять один голос на несколько групп.
4. **Согласование:** для каждого слова вычисляется длительность пересечения с интервалами каждого участника. Выбирается максимальное покрытие. Если одновременно активны разные участники не менее 40 мс и 20% длительности слова, используется `overlap`. Обычная граница между последовательными говорящими не считается одновременной речью. Непокрытое слово получает `unknown`.
5. **Реплики:** соседние слова одного участника объединяются при паузе не более 700 мс и общей длине не более 15 секунд. Параметры изменяются в конфигурации. Это границы реплик, а не ограничение длительности файла. Полностью нераспознанные диаризованные речевые области от 200 мс получают `[Неразборчиво]`. При отсутствии ASR и речевых областей экспортируется пустой массив.
6. **LLM:** локальная GGUF-модель обрабатывает каждую реплику, при необходимости делит текст для контекста. Разрешены пунктуация и регистр. Списки слов до и после сравниваются; добавления, удаления, перестановки и замены отклоняются. Метки и говорящие вообще не передаются модели. При сбое сохраняется исходная реплика с предупреждением. В отличие от разрешённых FR-08 исправлений слов ASR, этот MVP намеренно использует более строгую политику: автоматическое исправление слов отключено.
7. **Экспорт:** только `transcript` и четыре поля реплики; UTF-8 без BOM, LF, отступ 2. Сначала записывается временный файл, затем заменяется целевой. Ошибка экспорта не затрагивает исходное аудио и не заменяет старый экспорт неполными данными.

ASR, диаризация и LLM загружаются последовательно. Промежуточный PCM удаляется после обработки, включая обработанные исключения. После принудительного завершения ОС временный каталог может остаться; автоматическая очистка осиротевшего кэша пока не реализована в CLI.

## Проверка результата

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe -m dictophone validate result.json
.venv/Scripts/python.exe -m dictophone evaluate reference.json result.json
```

WER вычисляется после приведения к нижнему регистру и удаления пунктуации, с сохранением дефисов внутри слов. Это вспомогательная метрика: правила экспертов могут отличаться. WER не оценивает говорящих и временные границы. DER и ошибка меток в этом проекте автоматически пока не вычисляются.

`metrics.json` содержит общее время, RTF (включая LLM и основной экспорт), длительность, времена этапов, количество реплик и предупреждения. Время отдельной записи самого отчёта не включается. Текст и содержимое аудио в метрики/CLI-журнал не выводятся. Отказ LLM обозначается предупреждением; наличие JSON само по себе не подтверждает, что LLM успешно отработала — смотрите `llm_accepted_utterances`.

## Ограничения

- Проверена desktop-версия на CPU; перенос на другие платформы не входит в текущий этап.
- Memory map снижает расход памяти декодера, но модели могут создавать полные копии аудио. Для длинных файлов диаризация всей записи потребляет значительную память. Нет гарантии обработки произвольной длительности.
- Кластеризация всего файла сохраняет общую нумерацию участников; независимая обработка кусков диаризации без глобального сопоставления голосов пока не реализована.
- Диаризация и VAD могут ошибаться, особенно на коротких репликах, тишине, шуме и похожих голосах. `[Неразборчиво]` — эвристика по речевым областям без слов; достоверно обнаружить каждый неразборчивый участок невозможно.
- `overlap` зависит от пересекающихся интервалов, предоставленных диаризацией. Смешанный звук не разделяется, все голоса в нём отдельно не распознаются.
- Qwen 0.5B — компактный стартовый кандидат, его пригодность для русской пунктуации требует проверки. Защита слов ограничивает изменения, но не гарантирует правильность пунктуации и смысла.
- Конфигурация и модели считаются доверенными локальными файлами. Не публикуйте пользовательские аудиозаписи, сессии и результаты в репозитории.
