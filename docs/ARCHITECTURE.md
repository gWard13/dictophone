# Архитектура Python-конвейера

## Компоненты

| Модуль | Назначение |
|---|---|
| `backends.py` | PyAV-декодер, faster-whisper, sherpa-onnx, локальная GGUF LLM |
| `core.py` | Независимые типы данных, согласование, защита LLM, JSON и WER |
| `pipeline.py` | Последовательность этапов, освобождение ресурсов, резервные результаты |
| `clips.py` | Точная нарезка локальных подкастов и метаданные смещений |
| `cli.py` | Команды запуска и сообщения без содержимого аудио/текста |
| `refinement.py` | Независимая перепроверка коротких интервалов по голосовым эмбеддингам |

Порядок: декодирование → диаризация → ASR со словами и метками → согласование → LLM → проверка → экспорт.

В базовом профиле ASR получает всю запись. В экспериментальном speech-guided профиле диаризованные интервалы определяют окна ASR: соседние интервалы одного голоса объединяются при паузе до 1500 мс, перекрывающиеся голоса обрабатываются совместно, добавляется до 500 мс контекста. Соседние окна разделены по середине промежутка, без дублирования отсчётов. К меткам ASR прибавляется глобальное смещение окна. Если диаризация не вернула интервалы, ASR получает весь файл.

Модели ASR, диаризации и LLM загружаются последовательно. PCM размещается во временном файле и открывается через memory map. Это не гарантирует постоянный расход памяти: модели могут создавать копии и промежуточные тензоры.

## Согласование

Каждое слово получает голос с максимальным суммарным временным покрытием. Одновременное покрытие разными участниками не менее 40 мс и 20% слова даёт `overlap`. Переход между последовательными голосами сам по себе не является overlap. Без пересечения с диаризацией — `unknown`.

ID кластеров нормализуются в `speaker_1`, `speaker_2` по первому появлению. Соседние слова одного участника объединяются до паузы 700 мс или длины реплики 15 секунд. ID стабильны в пределах одной записи; между независимыми подкастами или клипами они не сопоставляются.

## LLM и ошибки

LLM получает только текст; speaker_id и метки не передаются. Разрешены пунктуация и регистр. Проверка сравнивает последовательности слов и чисел; лексические изменения отклоняются.

- Ошибка ASR завершает обработку.
- Ошибка диаризации сохраняет текст с `unknown` и предупреждением.
- Ошибка LLM/проверки сохраняет исходный текст соответствующей реплики.
- Нехватка памяти/диска считается критической ошибкой.
- При отсутствии речи экспортируется пустой массив.

## Данные

Экспорт содержит только `transcript` с `speaker_id`, `start_ms`, `end_ms`, `text`. Метрики и предупреждения пишутся отдельно по запросу. Отладочная сессия с исходными словами/репликами сохраняется только с `--session`.

Нарезка подкаста создаёт новый MP3 с нулевым началом. При пакетной нарезке исходное смещение записывается в manifest.json. Для внешнего эталона нужно использовать ту же временную шкалу клипа.

## Перепроверка коротких реплик


Опция `diarization.refine_short_turns` по умолчанию выключена. После первичной диаризации:

1. Для каждого речевого интервала отдельно вычисляется голосовой эмбеддинг.
2. По первичным ID строятся нормированные центроиды с весом длительности. Перекрывающиеся голоса не используются как чистые образцы.
3. Для интервалов до 3000 мс повторно сравниваются голоса. Сам проверяемый интервал исключается из собственного эталона (leave-one-out).
4. Для голоса-образца требуется минимум 3500 мс других интервалов. Переназначение допускается только при cosine similarity не менее 0,6 и отрыве от второго кандидата не менее 0,15.
5. Не создаются новые участники, не меняются временные границы диаризации, не используется текст и не фиксируется число говорящих. Решения принимаются относительно исходных меток без каскада предыдущих переназначений.
6. После уточнения снова строятся ASR-окна и выполняется настоящее распознавание. Поэтому текст и его метки могут отличаться от прежнего прогона.

Косинусные значения не являются калиброванной вероятностью правильности. Сходная музыка может влиять на эмбеддинги. Короткие, обработанные звуковыми эффектами голоса остаются сложными.


## Модели и конфигурации

| Этап | Реализация |
|---|---|
| Декодирование | PyAV, mono float32 PCM 16 кГц |
| ASR | faster-whisper / CTranslate2, Whisper small, CPU INT8 |
| Диаризация | sherpa-onnx: pyannote segmentation 3.0, 3D-Speaker embeddings, автоматическая кластеризация |
| LLM | Qwen 0.5B GGUF через llama-cpp-python, CPU |

Профили находятся в [config](../config/README.md): базовый, speech-guided и short-turns. Дополнительные веса WeSpeaker использовались только для диагностики и не являются зависимостью этих профилей.

LLM использует инструкцию менять только пунктуацию и регистр, сохраняя слова, числа и порядок. JSON-ответ проверяется программно. Промпт и параметры фактического вызова находятся в [backends.py](../src/dictophone/backends.py).

Границы ответственности: протокол данных — [PROTOCOL.md](PROTOCOL.md), известные проблемы — [LIMITATIONS.md](LIMITATIONS.md), измерения и история экспериментов — [TEST_RESULTS.md](TEST_RESULTS.md).

## Первичные источники

- ASR: https://github.com/SYSTRAN/faster-whisper
- Диаризация: https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/offline-speaker-diarization.py
- LLM API: https://llama-cpp-python.readthedocs.io/en/latest/api-reference/
- GGUF: https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF

Будущий перенос на другую платформу должен сохранять реальные метки слов, общую шкалу времени и правила согласования. Форматы весов разных движков не взаимозаменяемы: CTranslate2-веса не загружаются непосредственно в whisper.cpp. При разбиении диаризации потребуется глобальное сопоставление голосов. Входные типы перечислены в протоколе; реализация Android пока не входит в этот репозиторий.
