# Передача разработчику Android

## Контракт

Вход конвейера — mono PCM 16 кГц. Времена наружу — целые миллисекунды от начала декодированной записи. Значения обрезаются диапазоном `[0, duration_ms]`. На границах слов сохраняется исходная шкала, включая паузы.

Промежуточные типы:

```text
Word(start_ms: int, end_ms: int, text: string)
Turn(start_ms: int, end_ms: int, speaker: string)
Utterance(speaker_id: string, start_ms: int, end_ms: int, text: string)
```

Сырые ID кластеров нормализуются в порядке первого появления. `unknown` используется при отсутствии пересечения с речевой областью или ошибке диаризации; `overlap` — при достаточном одновременном покрытии разными участниками. Пороги и обработка равенства покрытий находятся в `core.py`.

## Порядок переноса

1. Запустить диаризацию sherpa-onnx на телефоне с теми же ONNX и параметрами.
2. Выбрать Android-ASR с настоящими временными метками слов/токенов. Кандидат — whisper.cpp с эквивалентными Whisper small весами в его формате. Веса CTranslate2 из `model_dir` непосредственно в whisper.cpp не загружаются: нужен отдельный формат. Совпадение текстов и меток разных движков не гарантировано.
3. Передать результаты через `Word` и `Turn`. Если движок выдаёт только сегменты, нельзя равномерно раздавать метки словам и считать это точной привязкой: потребуется реальное выравнивание либо отдельный согласованный сегментный алгоритм.
4. Переписать `canonical_turns`, `choose_speaker` и `align` на Kotlin/C++, используя тесты как примеры поведения.
5. Запустить GGUF через llama.cpp с CPU, ограниченным контекстом и тем же промптом. Портировать защиту `guarded_text`; восстановить совместимые Unicode-правила выделения слов.
6. Реализовать резервные сценарии: ASR — ошибка; диаризация — unknown; LLM — исходный текст и кнопка повтора.
7. Хранить исходные реплики для повтора LLM только в текущей сессии приложения. Python `--session` — отладочный механизм, не требование постоянного Android-хранилища.
8. Реализовать JSON через Storage Access Framework. Никаких внутренних метрик или предупреждений в `transcript` не добавлять.
9. Проверить расход памяти на устройстве с 4 ГБ. Если не помещается, выбрать меньшую ASR-модель, снизить контекст LLM и организовать обработку ASR кусками с глобальными смещениями. Для диаризации при разбиении потребуется глобальное сопоставление голосовых эмбеддингов.
10. Реализовать установку моделей при первом запуске и очистку кэша, состояния/вкладки/пагинацию по ТЗ. Это ответственность Android-обвязки.

Обрабатывать аудио на Python-сервере с телефона при проверке запрещено. Python-конвейер — локальный исследовательский инструмент и проверочный эталон алгоритма, а не удалённый backend приложения.
