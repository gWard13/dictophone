# Протокол данных и экспорт

## Вход

Один доступный локальный MP3; язык задаётся явно (`ru` или `en`). Декодер преобразует аудио в mono float32 PCM 16 кГц без изменения оригинала. Отсчёт времени начинается с начала декодированной записи; паузы сохраняются в общей шкале.

## Итоговый JSON

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

Это пример структуры, а не заранее подготовленный результат модели.

| Поле | Тип и правило |
|---|---|
| transcript | Массив реплик |
| speaker_id | `speaker_1`, `speaker_2` и далее; `unknown` при неопределённости; `overlap` для одновременной речи |
| start_ms | Целое число, начало в миллисекундах |
| end_ms | Целое число, окончание в миллисекундах |
| text | Непустая строка, при необходимости `[Неразборчиво]` |

Должно выполняться `0 <= start_ms <= end_ms <= duration_ms`. Реплики отсортированы по start_ms; пересечение интервалов допустимо. При отсутствии речи результат — `{"transcript": []}`. Дополнительные поля с именем аудио и диагностикой в экспорт не включаются.

Формат записи: UTF-8 без BOM, переводы строк LF, отступ два пробела. Экспорт сначала записывается во временный файл, затем атомарно заменяет назначение. Неполный результат не должен заменять существующий экспорт.

Схема: [transcript.schema.json](../transcript.schema.json). Фактический валидатор в [core.py](../src/dictophone/core.py) дополнительно проверяет сортировку и взаимосвязь временных границ; декларативная схема не выражает все эти проверки.

## Промежуточные типы

```text
Word(start_ms: int, end_ms: int, text: string)
Turn(start_ms: int, end_ms: int, speaker: string)
Utterance(speaker_id: string, start_ms: int, end_ms: int, text: string)
```

Меткам слов, полученным из окна ASR, прибавляется смещение окна. Нельзя заменять настоящие метки равномерным распределением времени по словам. ID сырых кластеров нормализуются в порядке первого появления, поэтому после формирования реплик в видимых номерах возможны пропуски.

## Нарезка

Время в расшифровке отсчитывается от начала импортированного клипа. Для перевода ко времени исходного выпуска прибавьте `source_offset_ms` из manifest.json. Пакетная нарезка сохраняет это смещение отдельно от JSON-расшифровки.

## Метрики и отладочная сессия

`--report` сохраняет отдельный JSON: длительность, полное время обработки, RTF, времена этапов, число реплик, предупреждения, число принятых ответов LLM и автоматических переназначений коротких интервалов. RTF — время обработки, делённое на длительность аудио. Время записи самого отчёта не входит в измерение.

`--session` явно сохраняет приватные ASR-слова, речевые интервалы и исходные реплики для `retry-llm`. Без этого параметра сессия на диск не записывается. В метрики и обычный диагностический вывод содержимое аудио/текст не включается.

## Резервные сценарии

- Сбой ASR завершает обработку.
- Сбой диаризации сохраняет ASR с `unknown` и предупреждением.
- Ошибка перепроверки коротких реплик сохраняет первоначальную диаризацию с предупреждением.
- Сбой LLM/проверки сохраняет исходный ASR соответствующей реплики.
- Ошибка экспорта сообщает о неуспехе и не удаляет исходное аудио.
