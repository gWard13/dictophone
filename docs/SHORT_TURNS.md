# Автоматическая перепроверка коротких голосовых интервалов

## Задача и фактический результат

В тестовом вступлении короткая заставка перед основным монологом относилась к голосу ведущего. Пользователь указал, что её произносит другой участник, speaker_2. Ручные изменения и предопределённые назначения ID исключены.

Новый профиль **автоматически отделил короткую заставку от ведущего**, но назначил её speaker_1, а не speaker_2. Поэтому точное исправление по пользовательской разметке **не достигнуто**. Результат не объявляется правильной диаризацией только из-за числа голосов или появления границы.

В реальном прогоне 00:00–01:00 получено 7 реплик, 3 группы и одно автоматическое переназначение короткого интервала. Заставка выделена примерно в 23,814–26,214 с, основной голос начинается примерно с 26,921 с. Это модельные оценки, не ручные границы.

Время — 56,937 с на 60 с аудио, RTF 0,949. LLM приняла 5 текстов, для двух сохранён ASR. Дополнительная обработка не является оптимизацией скорости. Прогон локальный; эталонные WER/DER отсутствуют. Метрики без текста находятся в `artifacts/validation/short-turns.metrics.json`.

## Алгоритм

Опция `diarization.refine_short_turns` по умолчанию выключена. После первичной диаризации:

1. Для каждого речевого интервала отдельно вычисляется голосовой эмбеддинг.
2. По первичным ID строятся нормированные центроиды с весом длительности. Перекрывающиеся голоса не используются как чистые образцы.
3. Для интервалов до 3000 мс повторно сравниваются голоса. Сам проверяемый интервал исключается из собственного эталона (leave-one-out).
4. Для голоса-образца требуется минимум 3500 мс других интервалов. Переназначение допускается только при cosine similarity не менее 0,6 и отрыве от второго кандидата не менее 0,15.
5. Не создаются новые участники, не меняются временные границы диаризации, не используется текст и не фиксируется число говорящих. Решения принимаются относительно исходных меток без каскада предыдущих переназначений.
6. После уточнения снова строятся ASR-окна и выполняется настоящее распознавание. Поэтому текст и его метки могут отличаться от прежнего прогона.

Косинусные значения не являются калиброванной вероятностью правильности. Сходная музыка может влиять на эмбеддинги. Короткие, обработанные звуковыми эффектами голоса остаются сложными.

## Диагностическая проверка второй модели

Дополнительно локально проверена WeSpeaker VoxCeleb ResNet34 из официальной коллекции sherpa-onnx. Она, как и исходная 3D-Speaker, дала наибольшее сходство спорного фрагмента с первой группой. Это расхождение с пользовательской разметкой, а не доказательство ошибки пользователя. Альтернативные веса не являются зависимостью нового профиля и не включены в Git.

Источник: https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models

## Проверки

38 локальных автоматических тестов прошли, включая новое переназначение по эмбеддингу, отказ при неоднозначности, исключение собственной реплики из эталона и запрет переназначения одновременной речи. Тесты контролируют алгоритм и не подтверждают правильность ID в реальном примере.

```powershell
python -m dictophone run "C:/audio/clip.mp3" --config config/pipeline.short-turns.json --output artifacts/runs/clip.json --report artifacts/runs/clip.metrics.json
```

Сохраняются исходный и экспериментальный профили. Ни один не заменяется автоматически из-за успеха на одном фрагменте. Следующий шаг для качества — проверка других embedding-моделей и отделения фоновой музыки на размеченных примерах, без подгонки назначения по известной фразе.
